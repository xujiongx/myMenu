# 产品需求文档（PRD）

> 产品：我的菜单（移动端点菜）· 版本：v0.1 · 状态：设计中 · 更新日期：2026-07-28

## 1. 文档信息

| 项目 | 内容 |
|------|------|
| 产品名称 | 我的菜单（My Menu） |
| 技术形态 | Next.js 移动端 H5 + Supabase（PostgreSQL / Auth）+ ImgBB（菜品图） |
| 文档目的 | 统一产品范围、页面交互、权限与验收标准，指导 UI / 前后端 / 测试 |

## 2. 背景与目标

### 2.1 背景

餐饮消费场景需要一款轻量移动端点菜工具：用户登录后按分类浏览菜品、加购结算、查看历史订单；管理员可维护菜品库（含图片）。

### 2.2 目标

- 账号密码登录，登录态可本地持久（支持过期）。
- 点菜页：左侧分类 + 右侧菜品列表，支持加减数量与结算。
- 我的页：用户信息、点菜记录、菜品管理（管理员）、切换账号。
- 菜品图片经服务端使用 `IMG_BB_API_KEY` 上传至 ImgBB，URL 写入数据库。

### 2.3 非目标（本期不做）

- 多门店 / 多桌台 / 扫码点餐（跨用户共享一张桌）。
- 支付收银台、优惠券、库存扣减。
- 桌面端多栏后台、复杂报表。
- 开放对外第三方 REST。
- 实时协同点菜（多人同桌实时同步）。
- 用户之间共享菜单 / 平台统一菜品库（本期每人独立菜单）。

## 3. 用户与场景

### 3.1 目标用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 普通用户 | 餐饮消费者 | 浏览分类点菜、下单、看自己的订单 |
| 管理员 | 门店维护人员 | 增删改菜品、上下架、上传图片 |

### 3.2 用户故事

1. 作为**用户**，我希望**用账号密码登录**，以便**安全访问我的点菜与订单**。
2. 作为**用户**，我希望**按分类浏览菜品并加减数量**，以便**快速组单结算**。
3. 作为**用户**，我希望**查看历史点菜记录**，以便**回顾消费**。
4. 作为**管理员**，我希望**新增/编辑/删除菜品并上传图片**，以便**维护前台菜单**。
5. 作为**用户**，我希望**切换账号时清空本机会话与购物车**，以便**不串号**。

## 4. 整体产品架构

### 4.1 页面架构

```mermaid
flowchart TB
  start[启动] --> auth{已登录?}
  auth -->|否| login[/login 登录页]
  auth -->|是| order[/ 点菜 Tab]
  login -->|成功| order
  order <--> mine[/mine 我的 Tab]
  mine --> records[/orders 点菜记录]
  mine --> manage[/manage 点菜管理]
  manage --> dishEdit[/manage/dish 新增或编辑]
  mine -->|切换账号| login
```

1. 前置页：登录页（未登录强制进入）。
2. 主页 Tab1：点菜（默认首页）。
3. 主页 Tab2：我的。
4. 子页：点菜记录、点菜管理、菜品编辑（从我的进入）。

### 4.2 核心业务流程

打开应用 → 校验登录 → 未登录进登录页 → 登录成功进点菜页 → 选分类/加减菜品 → 结算生成订单 → 我的页查看记录 / 管理菜品 / 切换账号。

### 4.3 通用规则

| 规则 | 说明 |
|------|------|
| 权限 | 主业务页与接口均需登录；未登录拦截至 `/login` |
| 会话 | 登录态 + 用户信息本地缓存，支持过期失效 |
| 适配 | 移动端优先（建议 `max-w-md` 视口），支持常规滚动 |
| 加载 | 请求展示加载态；失败可重试 |
| 视觉 | 简约移动端点菜风：清晰分类栏、菜品卡片信息完整、底部双 Tab；登录页居中 LOGO + 表单，无冗余装饰 |

## 5. 功能需求

| 编号 | 模块 | 需求描述 | 优先级 | 验收要点 |
|------|------|----------|--------|----------|
| F-00 | 访问控制 | 无有效会话时中间件跳转 `/login` | P0 | 未登录无法进点菜/我的/管理 |
| F-01 | 登录 | 账号 + 密码；密码可显隐；非空校验 | P0 | 成功缓存会话并进点菜；失败清空密码并提示 |
| F-02 | 点菜页顶栏 | 标题「点菜」；预留搜索位（本期可不实现搜索） | P1 | 顶栏固定 |
| F-03 | 分类栏 | 左侧分类列表，默认选中第一项，选中高亮 | P0 | 点击切换右侧列表 |
| F-04 | 菜品列表 | 图、名、价、简介、加减数量；空态「该分类暂无菜品」 | P0 | 仅展示上架菜品 |
| F-05 | 滚动联动 | 右侧滚动高亮左侧分类；点击分类滚动到对应区块 | P0 | 有分类锚点时联动正确 |
| F-05a | 菜品详情 | 点击菜品打开详情弹层，可加减数量 | P1 | 图/名/价/简介与加购可用 |
| F-06 | 购物车栏 | 已选数量、总价、结算 | P0 | 数量为 0 时不可结算或提示 |
| F-07 | 结算 | 生成订单与明细，清空购物车 | P0 | 订单归属当前用户 |
| F-08 | 我的页头部 | 头像、昵称、账号 | P0 | 与登录用户一致 |
| F-09 | 点菜记录 | 列表：时间、菜品摘要、金额、状态；分页/触底加载 | P0 | 仅本人订单；无数据空态 |
| F-10a | 分类管理 | 每人增删改自己的分类（名称、排序）；有菜不可删 | P0 | 「我的」入口；互不可见 |
| F-11 | 菜品 CRUD | 分类、图、名称、单价、简介、上下架；归属当前用户 | P0 | 变更后仅本人点菜页更新 |
| F-12 | 切换账号 | 二次确认 → 清会话与购物车 → `/login` | P0 | 无残留登录态 |
| F-13 | 下拉刷新 | 点菜页可刷新分类与菜品 | P1 | 失败可重试 |

## 6. 详细页面说明

### 6.1 登录页

- 布局：居中 LOGO + 账号框 + 密码框（显隐）+ 登录按钮。
- 账号：数字字母，禁特殊符号与空格；空则提示「请输入账号」。
- 密码：默认隐藏；空则提示「请输入密码」。
- 成功：缓存登录态、账号、昵称、头像、角色；跳转点菜 Tab。
- 失败：保留账号、清空密码，提示「账号或密码不正确」或网络错误。
- 无返回：避免未登录进入主页。

### 6.2 点菜页

- 结构：顶栏 | 左分类 | 右菜品 | 购物车栏 | 底 Tab。
- 分类过多时左侧独立滚动；右侧独立滚动。
- 加减：数量 ≥ 0；为 0 即取消选购。
- 结算成功 Toast/提示后清空本机购物车。

### 6.3 我的页

- 用户信息区 + 功能列表：点菜记录、点菜管理、切换账号。
- 点菜管理：列表含上/下架；新增/编辑表单字段见 F-11；删除二次确认。

## 7. 数据需求（摘要）

详见 [database-design.md](./database-design.md)。

| 域 | 关键字段 |
|------|----------|
| 用户 | 账号、密码（加密）、昵称、头像、角色、会话有效期 |
| 分类 | 分类 ID、名称、排序 |
| 菜品 | 分类、名称、图片 URL、单价、简介、上下架、操作人、时间 |
| 订单 | 订单 ID、用户、时间、明细、总金额、状态 |

## 8. 异常场景

| 场景 | 处理 |
|------|------|
| 网络异常 | 「网络异常，请重试」+ 可手动刷新 |
| 账号密码错误 | 「账号或密码不正确」 |
| 无菜品 / 无订单 | 空状态文案 |
| 登录过期 | 清会话，强制 `/login` |
| 菜品表单不完整 | 字段级提示 |
| 同名菜品 | 可提示重复（同分类或全局策略在库表唯一约束中定） |
| 无管理权限 | 「当前账号无管理权限」 |

## 9. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 首屏目标 ≤ 1.5s（合理网络）；Tab 切换流畅；分类/列表滚动无卡顿 |
| 兼容 | 主流手机浏览器；适配安卓 / iOS WebView |
| 安全 | 密码不明文；密钥仅服务端；业务接口鉴权；订单按用户隔离 |
| 图片 | 上传走服务端 ImgBB，不在客户端暴露 `IMG_BB_API_KEY` |

## 10. 里程碑

| 阶段 | 交付 |
|------|------|
| M0 | 文档齐全（本目录）、环境与表结构确定 |
| M1 | 登录 + 点菜浏览 + 购物车结算 |
| M2 | 点菜记录 + 菜品管理（含 ImgBB 上传） |
| M3 | 权限打磨、缓存与部署上线 |
